Author: pravallikachejerla <pravallikachejerla@users.noreply.github.com>
Date:   Sun Oct 25 17:14:06 2026 +0000

    Wave 1: implement five stabilisation repairs
    
    Implements the five repairs approved in the prior failure-map-and-wave-1
    proposal. Each repair is linked to a specific incident and underlying
    condition, and is verified by reproduction, regression, and
    failure-injection tests.
    
    F-02 (STAB-02 / INC-2026-0611-1): wire Consumer.ProcessIdempotent so
    broker redeliveries are detected and skipped rather than producing
    duplicate business effects.
    
    F-05 (STAB-05 / INC-2026-0705-1): add batch.Process production entry
    point that routes through RunStreaming with a bounded window, so peak
    retained-object count is independent of batch size.
    
    F-08 (STAB-08 / INC-2026-0728-1): route orders.Service.Approve through
    a CAS helper that uses TransitionOrderSafe, so concurrent transitions
    on the same order cannot both succeed.
    
    F-11 (STAB-11 / INC-2026-0818-1): switch fulfilment.ScopeFn from
    GlobalScope to TenantScope so breaker state cannot leak across tenants.
    
    F-04b (STAB-04 config half / INC-2026-0627-1): derive Pool.JobTimeout
    from the fulfilment.dependency_timeout_ms config key, so a slow
    dependency cannot occupy a worker for longer than the configured
    timeout plus a small margin.

10. Rollback Procedure

Rollback to Baseline

  1. Stop the running API process: kill $(pgrep -f /tmp/api-baseline)
  2. Checkout the baseline commit: git checkout 5b4e8d8
  3. Rebuild: go build -o /tmp/api-baseline ./cmd/api
  4. Restart: /tmp/api-baseline &
  5. Verify: curl -s http://localhost:8081/healthz
